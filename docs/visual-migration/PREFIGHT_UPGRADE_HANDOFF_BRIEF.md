# Бриф для Claude Design — экран прокачки (drill-down ядро → кристалл → грань)

> Контекст: временное окно перед боем (MVP, Этап 1). Поток уже собран в Claude
> Code: **выбор ядра (/play) → прокачка (/play/upgrade) → «В бой» → арена**. Экраны
> выбора и арены готовы. Нужен хэндоф **экрана прокачки** для порта на Vue.
> Решения — Notion → Game Design + Visual System (06.06.2026).

## Что нужно отдать (формат хэндофа)

Один автономный пакет, как прошлые хэндофы Claude Design:

1. **`upgrade.html`** — разметка экрана.
2. **`styles.css`** — стили (без фреймворков, без бандлера).
3. **`script.js`** — vanilla JS: drill-down + рендер из данных, без зависимостей.
4. **`data.js`** — данные ядер → кристаллов → граней (заглушки ок, см. форму ниже).
5. **`README.md`** — заметки для порта на Vue (см. «Контракт порта»).

Чистая статика, HTML/CSS/vanilla JS. Никакого React/Babel/сборки — это уходит в
порт на Vue, и чем чище разделение data / pure-функции / методы, тем дешевле порт.

## Экран и навигация

- **Drill-down от ядра** (решено 06.06): тап по ядру → раскрываются его
  **кристаллы** → тап по кристаллу → видны его **грани**. Три слоя: Ядро → Кристалл
  → Грань. Хлебные крошки / кнопка «назад» между слоями.
- **Грани с отказом**: вкачать все нельзя (черновик «5 граней, открыть 3» — числа
  проверяемые). Грань зажигается за ресурс; виден сразу весь кристалл, гаснущие/
  потолок — на усмотрение, но «отказ» должен читаться.
- Внизу экрана — кнопка **«В БОЙ»** (в порте навесим переход на арену).
- Содержание граней — **заглушки** (название + короткое описание + стоимость). Оси
  характера ещё не зафиксированы, текст наполнит дизайн/геймдизайн позже.

## Цвет и дисциплина (важно)

- **Экран прокачки — канон-розовый `#FF0069`** (откат, решено 06.06). Per-core hue
  (цвет ядра) на этом экране НЕ используется — он живёт на экране выбора и на
  бойце на арене. Один источник свечения на экран.
- Допустимо показать, какое ядро прокачивается (имя + маленький чип его цвета), но
  акцент/свечение самого экрана — канон-розовый.
- Токены, под которые желательно лечь (есть в проекте, `.app-v2`):
  `--hex-primary: #FF0069`, `--bg-deep: #070811`, `--bg-panel: rgba(14,16,28,.85)`,
  `--text-mid`, `--text-dim`, `--font-display` (Archivo Black), `--font-body`
  (Space Grotesk), `--font-mono` (JetBrains Mono).

## Форма данных (`data.js`) — держать в этой структуре

Слой кристаллов углублён 06.06: **ядро → несколько кристаллов → грани** (НЕ
«грани сразу к ядру»). ID ядер должны совпадать с `src/data/cores.js`:
`natisk`, `naletchik`, `skala`, `zasada`.

```js
export const CORES = [
  {
    id: 'natisk',            // совпадает с src/data/cores.js
    name: 'Натиск',
    crystals: [
      {
        id: 'natisk-press',
        name: 'Кристалл давления',   // заглушка
        faces: [
          { id: 'f1', name: 'Грань A', desc: '…', cost: 1 },   // заглушки
          { id: 'f2', name: 'Грань B', desc: '…', cost: 1 },
          // …«5 граней, открыть 3» — числа черновые
        ],
        maxOpenFaces: 3,         // отказ: открыть можно не все
      },
      // …ещё кристаллы
    ],
  },
  // naletchik / skala / zasada — та же форма
];
```

## Контракт порта (то, что упростит перенос на Vue) — описать в README

Разнести на три слоя, чтобы порт был механическим:

- **Данные → store.** `CORES` / `CRYSTALS` уезжают в стор/composable. Не хардкодить
  в разметку — рендерить из данных.
- **Чистые функции** (рендер-хелперы, без состояния) — назвать явно, чтобы перенести
  как есть: `hexPts(...)` (точки гекса), `coreSVG(...)`, `shardSVG(...)` (кристалл),
  `faceHex(...)` (узел грани). Принимают данные/цвет → возвращают строку/SVG.
- **Методы** (мутации состояния): `setLevel(...)`, `openCrystal(crystalId)`,
  `toggleFace(faceId)` — станут методами компонента/действиями стора.

В README: краткая карта «что где» + какие функции чистые, какие трогают состояние,
и какие узлы — заглушки под будущие оси/числа.

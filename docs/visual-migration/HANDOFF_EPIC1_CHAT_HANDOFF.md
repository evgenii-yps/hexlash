## 4. Формат работы в чате — как разговаривать с пользователем

**Язык:**
- Простой русский, без жаргона.
- Термины — **сразу поясняй простыми словами** (feature flag = «вторая версия сайта на отдельном URL, старая продолжает жить»).
- Без «великолепно», «с радостью», «надеюсь поможет», без смайликов.
- Пользователь прямо сказал: *«ты со мной разговариваешь на сложном для меня языке»*. Если чувствуешь что усложнил — упрощай.

**Процесс:**
- Пользователь НЕ пишет код сам. Он утверждает решения и даёт задачи.
- Пользователь работает с Claude Code параллельно — он передаёт туда ТЗ из нашего чата.
- **Не прыгай сразу в код.** Сначала — отчёт (как понял / план / риски). Жди подтверждения. Только потом выполнение.
- После каждого шага — **короткий статус**, не ломись вперёд.
- Вопросов в каждом шаге — **минимум**. Только критичное. Если можешь решить сам по плану — решай сам.

**Что запрещено:**
- Пересматривать решения из §3 без явного запроса.
- Галлюцинировать факты о проекте. Проверяй через `project_knowledge_search` или спрашивай пользователя.
- Обещать сроки.
- Писать длинные рассуждения.

## 5. Разделение ролей — важный момент

**В этой среде (claude.ai) ты НЕ имеешь доступа к репо проекта.** У тебя есть:
- project knowledge (CLAUDE.md, skill-файлы, возможно фрагменты кода проекта — проверить через `project_knowledge_search`)
- прикреплённые документы (4 файла из §2)
- песочница `/mnt/user-data/` и `/home/claude/` для временных файлов

**Чего у тебя НЕТ:**
- прямой доступ к `/src/`, `/backend/`, `package.json`, `.git/` проекта
- возможность запускать `npm install`, `git checkout`, `npm run dev`

**Кто реально пишет код:** Claude Code. Он работает в другой сессии, на машине пользователя, у него есть доступ к диску и git. Пользователь передаёт ему задачи.

**Твоя роль:** планировать, писать ТЗ для Claude Code, помогать пользователю вести процесс, проверять логику, советовать по архитектуре, обновлять документы, готовить такие же handoff-документы при переходе между чатами.

**Как писать ТЗ для Claude Code:** обычным текстом со ссылками на секции HANDOFF_VISUAL_MIGRATION.md. Claude Code сам прочитает CLAUDE.md и исходники, сам проверит `package.json`. Не нужно пытаться писать за него готовый код без доступа к реальным файлам — он всё равно перепишет под актуальное состояние репо. Общие правила работы (read CLAUDE.md → отчёт → подтверждение → шаги) у Claude Code уже есть в системных инструкциях.

## 8. Карта ТЗ Эпика 1 (краткая версия)

Полное ТЗ — в `HANDOFF_VISUAL_MIGRATION.md` §10. Здесь — короткая навигация для нового чата.

**Цель Эпика 1:** пользователь открывает `hexlash.com/v2` → пустая 3D-комната с туманом + плёночное зерно / развёртка / виньетка. Старый `hexlash.com/` работает как раньше.

**Чек критериев готовности:**
- `hexlash.com/` — старый визуал, не сломано
- `hexlash.com/v2` — пустая 3D-комната + эффекты
- Ничего из старого кода не удалено
- CLAUDE.md обновлён: новая секция «v2 Migration»

**Шаги (из HANDOFF §10):**
1. Создать ветку `visual-v2` от `main`
2. Проверить версию Three.js в `package.json`, зафиксировать
3. Feature flag `/v2` — новые роуты с префиксом `/v2/*`
4. `AppV2.vue` (минимальный — только CanvasLayer)
5. `/src/styles/hexlash-v24.css` — токены + эффекты, импорт ТОЛЬКО в AppV2
6. `/src/scene/CanvasLayer.vue` — единый Three.js canvas, пустая комната
7. `/src/scene/sceneRegistry.js` + `renderLoop.js` — каркас
8. Тестовый роут `/v2` работает

**Что НЕ делаем в Эпике 1:**
- Не удаляем старый UI
- Не трогаем старый App.vue кроме добавления условия скрытия хедера/меню на `/v2`
- Не переносим бойцов, ринг, интерактивные объекты (это Эпик 2)
- Не трогаем бэкенд, Prisma, WebSocket
- Не добавляем ключи i18n

**Ролик снят с коммита `main` `5b0d765bff7a67ed4236ed8ef3c0cb6b15be6629`** (влит в ветку). `origin/main` с тех пор ушёл вперёд на 29 коммитов (до `702596ad`, баланс-фикс) — он в ролик **не входит**; для пересъёмки с ним нужен отдельный проход (бои придётся подбирать заново).

## Что сделал
1. **Пересборка 720p с музыкой B (без склейки)** — закрыта: все сверки пройдены (см. «Сверки»), файлы — `step4-rebuild-720p/`.
2. **Цвет.** Все 7 эталонов приняты и замерены только по 3D-сцене (без полосы браузера, панели задач и интерфейса игры: обрезка по каждому эталону + маски правой панели, карточек команд, углов; `tools/showcase/color/measure.py`).
   * **Итог подбора — тождественная коррекция** (баланс 1/1/1, гамма 1, контраст 1, яркость 0, насыщенность 1; параметры лежат в сценарии, блок `grade`). Почему: когда стенд и экран владельца смотрят **одной и той же камерой** (штатная камера игры, окно 2560×1300, `color/refmatch.mjs`), цвета совпадают почти до уровня округления:
     | | стенд | эталон |
     |---|---|---|
     | фон, остров / зал | 8·8·10 | 8·8·10 |
     | фон, арена | 9·10·15 | 9·10·15 |
     | плита пола, арена | 26·26·33 | 26·26·33 |
     | плита пола, остров | 21·21·27 | 21·20·26 |
     | плита пола, зал | 17·17·22 | 16·16·21 |
     | розовые трещины (яркое ядро) | 255·15·173 | 255·15·172 |
     | доля пересвета | 0,04 % | 0,04 % |
     Средняя разница по 18 парам — **0,29 уровня из 255**. Подобранные множители (≈0,93) делают её хуже (0,33), поэтому не применены (`color/fit-report.json`). Тёмный фон остаётся почти чёрным, пол и шестигранники — как на снимках, розовые трещины и цветные сердца не пересвечены (доля пересвета как у эталона).
   * Цифры яркости пола в кадрах ролика выше, чем на обзорных эталонах (0,13–0,19 против 0,10), но это **ракурс** (ближние планы, тот же свет), не цвет.
   * **Настоящая цветовая правка нашлась в кодировании.** Файлы раньше писались без меток цвета; обычный плеер для HD берёт матрицу BT.709, а кодировщик по умолчанию клал BT.601 — розовый уходил в оттенке. Замер на розовых пикселях исходного кадра (G-канал): остров — исходно 13, «как раньше» 41, **теперь 14**; арена — 26 / 51 / **29**. Теперь кадры пишутся по BT.709 (диапазон ТВ) с явными метками в x264 и контейнере; фон/пол сходятся со средней ошибкой ≈0,4–0,7 уровня (шум сжатия).
   * **Пары «до / после / эталон» для острова, арены, зала:** `color/pair-island.png`, `pair-arena.png`, `pair-hall.png` (в каждой: ролик «как раньше» · ролик итоговый · эталон владельца · стенд штатной камерой). Цифры — `color/pairs-report.json`.
3. **Размытие движения.** Четыре подкадра камеры на быстрых участках, затвор 180° кадра ролика, усреднение в линейном свете; двигается только камера (бойцы и сцена стоят как на этом кадре). Где: ворота 100–215 (перелёт камеры), дуэль 296–350 / 446–500 / 596–654 (смены планов, крен T1), SQUAD 0–54 и 470–502 (крен T1, рывок T2), зал 0–24 / 205–345 / 500–568 (вход T2, спуск, отъезд T3). Пример кадра без размытия и с ним — `blur/…png` (слева без, справа с).
   * Не размыто (камеру ведёт сама игра, подкадры невозможны): пролёт к кнопке после нажатия FIGHT на острове и в воротах.
4. **Финальный рендер:** мастер 1920×1080/60 и веб-версия 1920×1080/30, каждая со звуком и без. Веб-30 собрана из тех же 60-кадровых кадров: каждый кадр = среднее двух соседних (как затвор 180° при 30), а не выбрасывание каждого второго — иначе размытие почти пропало бы. Музыка B (сплошной кусок трека 0:24,71–1:19,31), −14,0 LUFS, истинный пик −1,5 дБ, длина 54,60 с, BAM на 0:49,70.
5. **Найдено и исправлено в стенде (не в игре):** (а) склейка кусков фильтром `concat` на 60 кадр/с обрезала ролик почти вдвое — склейка теперь идёт демуксером из кусков без потерь, длина 3276 кадров = 54,60 с проверена; (б) указанное длиной `-t` не обрезало хвост — теперь точное число кадров на кусок.

## Риски
* Подписи островов в воротах считает сама сцена по кадру; на размытых кадрах они стоят в середине смаза (мелочь).

* Если игра изменится в `main` и ролик придётся пересобрать: бои подбираются заново (сборка сама ловит смену цифр боя).

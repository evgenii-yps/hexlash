## Правка
Новый `src/scene/boutRandom.js` (`createRng`, `freshSeed`, mulberry32 — тот же, что зажимает зерно в замерах).
Каждый участник боя заводит свой генератор один раз: зерно берёт из общего потока в момент создания, дальше
с ним не связан. В игре зерно случайное → бои, как и раньше, разные. В замерах зерно повторяется → бой
повторяется шаг в шаг. Все три фабрики принимают необязательный `rng`.

## 1. Тест изоляции — на все виды боя (`scripts/bout-random-isolation.mjs`)

Каждый бой считается чисто и с «шумом картинки» (посторонний берёт числа из общего `Math.random`), исход сверяется до знака.

| вид боя | боёв | шум МЕЖДУ ШАГАМИ: прогонов / разошлись | шум ПЕРЕД созданием: прогонов / исход изменился |
| --- | --- | --- | --- |
| голые дуэли | 48 | 144 / **0** | 96 / 96 |
| сборки | 36 | 108 / **0** | 72 / 72 |
| клич | 48 | 144 / **0** | 96 / 96 |
| баффы (TOWEL, BUCKET, DICE по граням и со случайным броском, набор по правилу бота) | 132 | 396 / **0** | 264 / 264 |
| RAID 4×3 (игрок + 3 союзника против босса + 2 охраны, состав как в замере) | 8 | 24 / **0** | 16 / 16 |
| **итого** | 272 | **816 / 0** | 544 / 544 |

**Поправка к прежнему отчёту:** раньше я называл «1176 прогонов». Это была моя арифметическая ошибка. Верно: 816 прогонов с шумом между шагами (0 расхождений) и 544 с шумом перед созданием (изменились все — см. ниже), всего 1360. Запись «1176» в Notion надо поправить на 816.

**Шум перед созданием бойцов — что меняется и почему это не ошибка.** Боец, поле боя, обход преград и бросок кубика берут своё зерно из общего потока ОДИН раз, в момент создания. Поэтому, если картинка успела взять числа до создания бойцов, зёрна у бойцов другие — и бой другой. Это задумано: именно так бой в игре каждый раз получается новым. Важна граница: после создания общий поток бой уже не затрагивает, и ни одна частица, текстура или правка вида арены не может сдвинуть ход боя, который уже идёт. Тест считает такие прогоны отдельно и на код выхода не влияет; изоляцию доказывает именно «между шагами = 0».

## 2. Кубик DICE

- Где бросается: одна функция `rollDie()` (`src/data/buffBalance.js`), зовётся один раз при броске предмета из `services/buffs.js`. Раньше брала общий `Math.random` — то есть могла взять число «после картинки».
- Где рисуется: `scene/buffItems.js` только показывает уже выпавшую грань. Своих случайных чисел у неё два (угол довода по кругу и запасной выбор, если грань не передана) — это картинка, на бой не влияют; грань выбирает `rollDie`.
- Что сделано (коммит `9fcb39cf`): `rollDie(rnd = Math.random)` остаётся ОДНОЙ функцией на игру, но получает необязательный генератор; в `buffs.js` у боя свой генератор, пересеивается в `buffStartFight`. Грань по-прежнему одна на бросок.
- Контроль, что правка была нужна: при броске через общий поток 8 из 12 боёв с DICE расходятся при шуме; через генератор боя — 0 из 396.
- Суммы четырёх регрессий от этой правки не изменились (в них грань DICE зафиксирована).

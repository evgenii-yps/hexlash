# TZ_apex_gate_v1 — вершина закрыта, пока не горят четыре нижних

Ветка `claude/resonance-seven`, база `62451242` (плюс слияние с `main` `d8c14acc`). В `main` не сливалось.
Словарь ТЗ: **ГРАНЬ** = ветка (в коде `crystal`, a/b/c), **КРИСТАЛЛ** = шаг ветки (в коде `face`, 1..5). Вершина = кристалл 5.

## 1. Запрет (п.1)

Правило живёт в одном файле — `src/data/apexGate.js` (`apexOpen`, `apexOpenInBranch`, `withoutClosedApex`). Вершина недоступна, пока в ТОЙ ЖЕ грани не горят кристаллы 1–4. Стоит везде, где собирается набор:

| Место | Что сделано |
| --- | --- |
| `rosterState.toggleFacet` (хранилище бойца) | вершину нельзя зажечь без четырёх нижних; **погас любой из кристаллов 1–4 → горевшая вершина гаснет вместе с ним, очко возвращается** |
| `SparView.onFoeToggle` (соперник в SPAR) | то же, что выше, на дереве соперника |
| `upgradeTree.buildTree` | вершина без четырёх ГОРЯЩИХ нижних отбрасывается — старые сохранения с запрещённым набором чинятся сами |
| `foeCompose.randomLitIds` (боты) | выпавшая «одинокая» вершина меняется на случайный нижний кристалл — число кристаллов у бота сохраняется |
| `ForgeCore.vue` | кнопка «зажечь» для вершины не активна, причина — строка `forge.whyApexClosed` (интерфейсная строка; тексты кристаллов не тронуты) |
| `behavior.resolveBehavior` | защитный фильтр: запрещённая вершина, пришедшая со стороны, в бою не участвует ни своими сдвигами, ни наклонами, ни резонансом |

Итог: запрещённый набор нельзя собрать ни через интерфейс, ни через хранилище, ни через ботов, а если он всё же придёт — бой его не увидит. Правило половины, порядок «жёсткие нужды → очки» и `buildFighter.js` не тронуты.

**Прямая встреча** (одно ядро, все пары наборов, 200 зёрен на пару, `scripts/apex-h2h.mjs`), доля побед стороны с вершиной 5+2:

**Ключевой вопрос — вершина против второго резонанса:**

> **Сопоставимый выбор, а не «одно явно сильнее». Вершина в среднем чуть сильнее — 55.7% и 56.3% в прямой встрече (сдвиг +0.4 против −1.9/−2.2 п.п. к россыпи), — но знак зависит от ядра: у BULWARK вершина берёт 64–68%, у ONSLAUGHT два резонанса берут 54% (вершина 46%). Вершина заметнее меняет манеру (расхождение намерений 30.0 п.п. против 22.7–24.2), не ломая длину и дистанцию боя (вне радиуса 31.3% против 30.3%, медиана 50.8 против 52.2–52.7 с).**

Причина ONSLAUGHT — вершина этого ядра (`overload_strike` в ветке RAM, `lockdown` в CHASE, `rampage` в FRENZY) кладёт наклон на то намерение, которое ядро и так выбирает в 99% тиков (PRESS/STRIKE); второй резонанс даёт ему то, чего нет — HOLD/PRESS с другой ветки. Это вопрос прохода по числам, здесь не правится.

## 4. Четыре «поглощённых» вершины после запрета (п.4)

Счёт — в инструментированной копии `intentions.js` (только во временном рабочем дереве, в репозиторий не попадает; `scripts/apex-absorb.mjs`, 200 зёрен на набор, «включена» — тиков, где условие наклона истинно; «изменила выбор» — тиков, где выбор без этого наклона был бы другим). `docs/grani-tags/out/apex/absorb.json`.

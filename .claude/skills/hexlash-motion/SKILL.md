# hexlash-motion — движение

## Характер движения Hexlash

**Плавно и тяжело.** Вес и инерция. Медленный замах, резкий момент, весомый возврат. Не резко-роботно, не пружинисто-игриво.

Это правило одинаково для 2D-интерфейса и для моторики бойцов в 3D. Интерфейс и бой должны ощущаться из одного мира.

## 1. Тайминги — канон

```css
--hs-fast:  0.15s;   /* смена цвета / рамки */
--hs-hover: 0.22s;   /* подъём + ободок / свечение */
--hs-press: 0.12s;   /* просадка на нажатии */
```

| Событие | Длительность |
|---------|--------------|
| Смена цвета, рамки | 150ms |
| Hover: подъём + свечение | 220ms |
| Press: просадка | 120ms |
| Sheen (проход блика) | 600ms |
| Фейд между 3D-сценами | ~200ms |
| Выезд панели кабинета | 420ms |
| Idle-пульс FIGHT | ~3.4s, бесконечно |
| Кинематографический переход в режимы | 2.2–2.8s |
| Поворот телефона в RotateHint | 1.8s, бесконечно |

**Правило:** нажатие всегда быстрее ховера. Отклик на палец должен быть мгновенным; украшение может быть медленным.

## 2. Easing — канон

```css
--hs-spring:   cubic-bezier(0.22, 0.61, 0.36, 1);  /* пружина: ховер, лёгкий подъём */
--ease-settle: cubic-bezier(0.20, 0.80, 0.20, 1);  /* прилёты: мягко, без перелёта */
--ease-weight: cubic-bezier(0.55, 0.00, 0.12, 1);  /* тяжёлый хром, плиты, двери */
```

| Что двигаем | Кривая |
|-------------|--------|
| Элемент прилетает / появляется | `--ease-settle` |
| Хром-кнопка, крупная плита, дверь | `--ease-weight` |
| Лёгкий hover-подъём | `--hs-spring` |
| Затухание / исчезание | `ease-out` или `--ease-settle` |

❌ `linear` — только для бесконечного вращения и полос прогресса.
❌ `ease-in-out` по умолчанию — читается ватно, в этом проекте не используем.
❌ Перелёт/отскок (`overshoot`, bounce) — противоречит характеру «тяжело».

## 3. Появление экрана — стаггер

Элементы прилетают не разом, а лесенкой снизу вверх по важности.

- Класс входа в магазине — `sb-rise`.
- Шаг стаггера 40–60ms.
- **Якорь появляется последним.** На доме FIGHT прилетает после всех остальных — так взгляд заканчивает на нём.
- Смещение при входе маленькое: 8–16px, не «влетает с края экрана».

## 4. Свечение в движении

- **Idle-пульс — только у якоря.** Один на экран. Всё остальное в покое неподвижно.
- Hero-bloom карточки в магазине — `sb-pulse`, медленный и мягкий.
- Sheen (блик по поверхности) — **один проход** на ховер, не циклом.
- Пульс никогда не должен быть быстрее 2s: быстрое мигание читается как тревога/ошибка.

## 5. Переход между сценами

Тяжёлых 3D-сцен три: дом · PVE · арена (плюс пространство). Каждая собирается заметное время, и её сборку игрок видеть не должен.

| Куда | Что |
|------|-----|
| В бой (`/play/arena`) | Полный Fight-Card со счётчиком |
| Дом ↔ PVE ↔ пространство | Фейд ~200ms |
| На 2D-экран при активном оверлее | Оверлей закрывается (страховка) |

**Снятие оверлея — по реальному сигналу готовности, не по таймеру.** Сцена эмитит `hexlash:<name>-ready` из первого отрисованного кадра под per-mount латчем. Страховка по времени существует (арена 8с, фейд 3с) — но это аварийный выход, а не механизм.

## 6. Кинематографический переход (в работе)

Нажатие FIGHT получает переход ~2.2–2.8с:

```
растворение интерфейса
  → уход камеры от дома
  → холодная дымчато-серая пелена
  → матовый знак HEXLASH
  → плиты режимов поднимаются снизу
```

Знак HEXLASH остаётся **матовым** — правило бренда «логотип без свечения» действует и здесь.

Архитектурная рекомендация: не строить четвёртую тяжёлую сцену, а поселить дом и плиты режимов **в одном мире** и просто уводить камеру. Файлы: `modePlates.js`, `transitionFlight.js`, `modePlateTags.js`.

⚠️ Статус: реализация на ветке, **не смержено**, ждёт приёмки. Открыты: замер производительности на телефоне, возврат сторожа FPS, цвет тумана, начертание 3D-знака.

## 7. `prefers-reduced-motion` — обязательно

Каждая анимация обязана иметь тихий вариант. Это не опция.

```css
@media (prefers-reduced-motion: reduce) {
  /* Оставляем: цвет, тень, opacity.
     Убираем:   transform, вращение, стаггер, sheen, пульс. */
}
```

Конкретно:
- `.hs-chrome` под reduced-motion меняет только цвет и тень — без `translateY`, без `scale`, без sheen.
- `RotateHint` показывает статичный телефон без вращения.
- Стаггер входа отключается: элементы просто появляются.
- Переходы между сценами остаются (они несут смысл «идёт загрузка»), но без движения — только затемнение.

## 8. Моторика бойца (3D) — тот же характер

Подробности — скил `hexlash-combat`. Здесь только принцип:

- **Медленный замах → резкий момент удара → весомый возврат.**
- После удара — «выдох»: короткое оседание плеч и таза, плавный blend обратно в движение. Удар не щёлкает в стойку.
- Перемещение — настоящий переступ: колено сгибается, стопа отрывается и ставится, ноги чередуются, амплитуда нарастает со скоростью.
- Разгон, торможение и поворот — плавные. Щелчков нет.
- Ритм боя дышит: дуга движения → короткий устой (0.7–1.6с). Бойцы не суетятся непрерывно.
- Комбо оседает глубже и дольше, чем джеб. Сила читается через глубину отдачи.

## 9. Производительность

Игра целится в телефон. Анимация не должна ронять кадры.

- Анимируй **только** `transform` и `opacity`. Не `width`, `height`, `top`, `left`, `box-shadow` в цикле.
- `will-change` — точечно и временно, не на всём подряд.
- Постоянных бесконечных анимаций на экране — минимум: один idle-пульс.
- `backdrop-filter` дорогой. Он уже есть в хром-семье (`blur(8px)`) — не размножать.
- Новую тяжёлую анимацию проверяй **на телефоне**, не в десктопном браузере.

## 10. Антипаттерны

| ❌ Нельзя | ✅ Вместо |
|-----------|----------|
| Отскок / перелёт | Мягкое прибытие `--ease-settle` |
| Ховер быстрее нажатия | Press 120ms < hover 220ms |
| Несколько idle-пульсов на экране | Один, у якоря |
| Sheen циклом | Один проход на ховер |
| Анимация без reduced-motion-варианта | Всегда тихий вариант |
| Снятие загрузки по таймеру | По сигналу готовности сцены |
| Анимация `width` / `top` / `left` | `transform` |
| Мигание быстрее 2s | Медленный пульс |
| Элемент влетает с края экрана | Смещение 8–16px |
| `ease-in-out` по умолчанию | Канонные кривые из §2 |

# hexlash-review — самопроверка перед сдачей

Прогоняй **до** того, как сказать «готово». Владелец не разработчик — он проверяет глазами, и его время дороже твоего.

## 1. Дисциплина визуала

- [ ] На экране **в покое** ровно одно геройское свечение (плюс максимум одно ценностное кольцо).
- [ ] Розовый на экране только один — `#FF0069`. Легаси `#FF066F` отсутствует.
- [ ] Розового нет на вторичных кнопках, на хром-панели, на логотипе.
- [ ] Ни в одном элементе не встречаются розовый + цвет ядра или два ядра.
- [ ] Цвет ядра применён как **свет** (bloom / ободок / глиф), а не как заливка предмета.
- [ ] Свечения нет на SOON, OWNED, disabled, основном тексте.
- [ ] Шрифты только Saira Condensed + JetBrains Mono. Никаких Anonymous / Impact / Archivo Black.
- [ ] Основной текст `#EDEDF1`, не `#FFFFFF`.
- [ ] Новых цветов и токенов не заведено (или заведены с явного согласия владельца).

Быстрый тест: скриншот в покое → прищуриться → сколько ярких пятен? Одно — хорошо, три — переделывать.

## 2. Поведение элементов

- [ ] У каждого интерактива есть все шесть состояний: rest · hover · active · focus-visible · disabled · loading.
- [ ] `focus-visible` реально виден и **без** блума. `outline: none` без замены отсутствует.
- [ ] Press (120ms) быстрее hover (220ms).
- [ ] Тач-зоны ≥ 44×44, просвет между целями ≥ 8px.
- [ ] Ничего важного не спрятано за hover — на телефоне hover'а нет.
- [ ] Подпись кнопки соответствует тому, куда она ведёт.
- [ ] Заглушки выглядят заглушками: матово, `#5D5D66`, без свечения.
- [ ] Модалка закрывается крестиком, кликом по фону **и Esc**.
- [ ] Числа, которые меняются, — `tabular-nums`, не прыгают.

## 3. Движение

- [ ] `prefers-reduced-motion` уважается: transform / вращение / стаггер / sheen / пульс выключаются, цвет и тень остаются.
- [ ] Idle-пульс на экране один — у якоря.
- [ ] Sheen — один проход, не цикл.
- [ ] Анимируются только `transform` и `opacity`.
- [ ] Ничего не мигает быстрее 2s.
- [ ] Тайминги и кривые — токены `--d-*` / `--e-*`, не свои числа.

## 4. Мобильный

- [ ] Проверено на узком экране, а не только на десктопе.
- [ ] Проверено по `pointer: coarse`, а не только по ширине.
- [ ] Портрет не ломается (даже если рекомендуем ландшафт).
- [ ] Горизонтального скролла нет.
- [ ] Новая тяжёлая анимация или 3D проверены **на телефоне**.

## 5. Код и архитектура

- [ ] Защищённые файлы не тронуты (или тронуты с явного разрешения — и об этом сказано в отчёте).
- [ ] Числа-настройки в CONFIG-блоке вверху файла; числа боя — только в `combatBalance.js`.
- [ ] Новых наборов переменных не заведено: только `src/styles/tokens.css`
      и `src/data/sceneTokens.js`.
- [ ] Поиск не находит `rgba(` со своими числами там, где есть токен.
- [ ] У каждого интерактивного элемента виден отклик на касание.
- [ ] Все тексты через i18n-ключи; удалённые элементы не оставили осиротевших ключей.
- [ ] Vuetify в новом UI не использован.
- [ ] Попутного рефакторинга нет — правка минимальная.
- [ ] Новая 3D-сцена имеет `meta.scene3d` и сигнал `hexlash:*-ready`.

## 6. Регрессия — что могло сломаться

Обязательный шаг: **найди всех потребителей того, что ты правил.**

```bash
grep -rn "имя-класса" src/
```

Особое внимание:

- [ ] Правил `.hs-strip` / `.hs-brand` / `.hs-bal` / `.hs-chrome` → проверил **дом И магазин И PVE**.
- [ ] Правил `home.css` → открыл магазин и убедился, что он цел.
- [ ] Правил `shop.css` под `body.home-shop-open` → убедился, что на доме панель по-прежнему фиксирована.
- [ ] Правил что-то в сцене → проверил, что бой не задет.
- [ ] Трогал i18n → нет пустых подписей.
- [ ] Трогал роутер → прошёл поток целиком: логин → дом → FIGHT → mode → pve/ground → ядро → прокачка → арена.
- [ ] Трогал загрузку → hard-load страницы и SPA-переход оба прикрыты.

## 7. Честность

- [ ] Ничего не выглядит рабочим, если оно не работает.
- [ ] Заглушечные числа не выдаются за настоящие.
- [ ] Прогресс загрузки — по реальным вехам, не по таймеру.
- [ ] Расхождения с прототипом проговорены, а не замолчаны.
- [ ] Всё, что не доделал, названо вслух.

## 8. Git

- [ ] Работа в ветке `claude/<описание>`, не в `main`.
- [ ] В `main` не мержил (мерж — только по явному «мержи» от владельца).
- [ ] Точка отката зафиксирована и написана в отчёте.
- [ ] Коммиты осмысленные, не «fix».

## 9. Отчёт владельцу

```
Что сделал:      1–3 предложения человеческим языком
Где посмотреть:  ветка / preview-ссылка / какой экран открыть
Что изменилось:  файлы простыми словами («экран магазина», «стили кнопок»)
Точка отката:    коммит
На что смотреть: 2–3 конкретные вещи для проверки глазами
Не сделал:       что осталось и почему
Риски:           что может быть задето
```

Формулировки: не «сделано», а **«готово к проверке»** — принимает владелец глазами на preview или проде.

## 10. Что записать в Notion после приёмки

По правилам проекта каждое решение фиксируется. Подскажи владельцу, что стоит записать:

- новое решение и **причину**;
- что поменялось в механиках или дисциплине;
- какие альтернативы отклонили и почему;
- дату, ветку, коммит и точку отката;
- если решение отменяет старое — старое **не удаляем**, помечаем устаревшим и ставим ссылку на новое.

Страницы: **Snapshot** (переписывается — «как сегодня»), **Decisions Log** (только дополняется), **Visual System** (если менялся визуальный язык).

# hexlash-frontend — архитектура фронта

## 1. Стек

| Слой | Что |
|------|-----|
| Каркас | **Vue 3** (`<script setup>`), Vite |
| Состояние | Vuex (легаси-модули) + локальные reactive-синглтоны для нового |
| Роутер | Vue Router 4 |
| 3D | **Three.js напрямую** — не R3F, не обёртки |
| Тексты | Кастомный i18n, **только локаль `en`** |
| UI-кит | Vuetify присутствует исторически. **В новом коде не использовать** — весь актуальный UI собран своим CSS |

## 4. Архитектура CSS

**Один экран — один CSS-файл.** Общее — в `home.css`, потому что верхняя панель шарится.

Порядок выбора, куда писать стиль:
1. Класс уже существует (`.hs-chrome`, `.hs-strip`, `sb-*`) → **переиспользуй**.
2. Стиль касается только одного компонента → `<style scoped>` внутри `.vue`.
3. Стиль нужен двум и более экранам → в соответствующий файл `src/styles/`, с префиксом семьи.

Префиксы классов:
- `hs-*` — дом / шаренная оболочка (`home.css`)
- `sb-*` — магазин (`shop.css`)
- `sh-*` — модальные листы магазина
- `hxl-*` — экран загрузки (в `index.html`)

**Не создавай новый токен, если можно взять существующий.** Список — `../hexlash-design/references/tokens.md`.

## 5. Ловушки — читай перед правкой стилей

Это места, где «безобидная» правка ломает другой экран. Все — реальные случаи из истории проекта.

### `home.css` шарится тремя экранами

`.hs-strip`, `.hs-brand`, `.hs-brandblock`, `.hs-bal` используют **дом, магазин и PVE**. Правка панели «на доме» немедленно меняет магазин.
→ Перед правкой: `grep` по классу во всём `src/`. Если потребителей больше одного — либо правь осознанно для всех, либо заводи отдельный класс.

### `.hs-bal` нельзя удалять

Баланс на доме не рендерится, но класс шарится с магазином. Удаление ломает магазин.

### `--hex-primary` живёт внутри `.app-v2`

В `:root` может оказаться легаси-значение. Компонент, вынесенный через `<Teleport>` за пределы `.app-v2`, получит неправильный розовый.
→ Кабинет игрока поэтому **не телепортируется**.

### `position: sticky` + `backdrop-filter` в магазине не работает

Пять заходов латания. Шапка дрейфует. Работает только цельный одностраничный скролл.
→ Не возвращать sticky, не делать flex-split.

### Развязка магазина через `body.home-shop-open`

При открытом магазине на `<body>` вешается класс; под ним в `shop.css` скроллером становится `.home-root`, а `.hs-strip` переходит в `position: relative`. `home.css` при этом **не трогается**.
→ Меняешь поведение магазина — правь `shop.css` под этим классом, а не `home.css`.

### Фон дома/PVE/арены — это 3D-купол, а не CSS

Тёмный купол **внутри** сцены с canvas-текстурой. «Зернистость / соты» крутятся ручками `hexMaxAlpha` / `dither` в конфиге купола (`HomeScene.vue`, `PveScene.vue`). CSS-фон оболочки `#08080A` плоский и ни при чём.
→ Жалоба «фон зернит» = править купол, а не CSS.

### Базовый шрифт игрового шелла — Space Grotesk, а не канон

`AppV2.vue` импортирует `hexlash-v24.css`, тот — `v24/tokens.css`, а тот ставит `font-family: var(--font-body)` прямо на `.app-v2`. То есть **на всех `/play/*` наследуемый базовый шрифт сейчас Space Grotesk**, хотя канон — Saira Condensed + JetBrains Mono. Плюс лишний запрос к Google Fonts за Archivo Black + Space Grotesk.

Спроектированные экраны шрифт задают сами и выглядят правильно; ловит только текст без явного шрифта.

→ **Новое всегда задаёт шрифт явно** (`--hs-disp` / `--hs-mono`, в магазине `--disp` / `--mono`). Токены `--font-display` / `--font-body` не использовать.
→ Приведение слоя к канону — **отдельная задача**, не попутная правка: у `.app-v2` есть живые потребители (`ArenaScene`, `FighterLabScene`, роутер, `main.css`), удалением файла не решается.

### CSS-бандл грузится блокирующе

Vite в прод-сборке кладёт `<link rel=stylesheet>` в `<head>`, ~19 КБ brotli — первый paint ждёт его. Это дефолт Vite, известный техдолг. Делать неблокирующим — отдельная правка с риском FOUC на всё приложение.

## 6. i18n

- Локаль **одна: `en`**. Русского текста в интерфейсе нет.
- Все строки — через ключи в `en.js`. Никакого текста хардкодом в шаблоне.
- Ключи группируются по экрану: `shop.*`, `space.*`, `rotateHint.*`, `mode.*`.
- **Удалил элемент — удали его ключ.** Осиротевшие ключи копятся; известные хвосты: `home.shopSub`, секция `profile.wallet.*` (до Этапа 2).
- Не заводи ключ «на будущее».

## 7. Конвенции кода

- `<script setup>` в новых компонентах.
- Числа-настройки — **вверху файла в CONFIG-блоке**, с комментарием, что крутит каждая ручка. Это принятый паттерн проекта: владелец должен уметь показать пальцем, какое число менять.
- Все числа боя — только в `src/data/combatBalance.js`. Нигде больше.
- Новое состояние, не связанное с игроком, — reactive-синглтон в `src/services/`, а не новый Vuex-модуль (см. `sceneTransition.js`).
- Мёртвый код не оставляем, но и не удаляем массово попутно: удаление — отдельная задача с отдельным откатом.
- Комментарии объясняют **почему**, а не что. «Так решено 26.06, альтернатива откачена» — полезно. «Устанавливаем opacity в 0» — нет.

## 8. Новая 3D-сцена — чеклист интеграции

1. Файл сцены в `src/scene/`, вид в `src/views-v2/`.
2. Роут с `meta.scene3d`.
3. Эмит сигнала готовности из первого отрисованного кадра: `window.__hex<Name>Ready` + событие `hexlash:<name>-ready`, под per-mount латчем.
4. Обработка сигнала в `main.js` (hard-load) и в `router.beforeEach` (SPA-переход).
5. CONFIG-блоки вверху файла сцены.
6. Защищённые файлы не тронуты — сцена собрана **своими копиями** по рецепту, а не флагом в чужой сцене.

Подробности — скил `hexlash-3d`.

# Система скилов Hexlash

Скилы — это инструкции, которые Claude Code читает **сам**, когда берётся за задачу в этом репозитории. Они лежат в `.claude/skills/` — только отсюда Claude Code их подхватывает автоматически.

Простыми словами: это памятка «как у нас принято», чтобы каждый раз не объяснять заново, какой розовый правильный, где нельзя ставить свечение и какие файлы трогать нельзя.

## Что где

| Скил | О чём |
|------|-------|
| **hexlash-core** | Читается первым. Иерархия источников правды, карта скилов, защищённые файлы, git-дисциплина, формат отчёта |
| **hexlash-design** | Палитра, шрифты, дисциплина свечения, ядра, логотип. `references/tokens.md` — все значения, `references/glow.md` — свечение подробно |
| **hexlash-ui** | Поведение: кнопки, шесть состояний, тач-зоны, панель, кабинет, модалки, заглушки, загрузка. `references/components.md` — спеки готовых компонентов |
| **hexlash-motion** | Тайминги, easing, стаггер, переходы между сценами, reduced-motion |
| **hexlash-frontend** | Vue, роуты, где какой файл, архитектура CSS, i18n, ловушки шаренных стилей |
| **hexlash-3d** | Three.js-сцены, камера, свет, купол фона, сигналы готовности |
| **hexlash-combat** | Автономный боец: намерения, оси, ядра и грани, баланс, лаборатория |
| **hexlash-handoff** | Работа по макету: правило переноса 1:1, что делать без макета |
| **hexlash-review** | Чеклист перед сдачей + что записать в Notion |

## Типовые связки

| Задача | Что грузить |
|--------|-------------|
| Новый экран интерфейса | core + design + ui + motion + frontend (+ handoff, если есть макет) |
| Правка кнопки / состояния | core + ui + design |
| Новая 3D-сцена | core + 3d + motion + frontend |
| Правка боя или баланса | core + combat |
| Перед пушем | core + review |

## Правила поддержки

1. **Изменилось решение по продукту — обнови скил.** Скил, отставший от Notion, хуже, чем его отсутствие: он уверенно врёт.
2. **Источник правды — не скил.** Порядок: живой код в `main` → Notion → `docs/design-handoff` → скилы. Скил объясняет правила, код показывает факт.
3. **Устаревшее не удаляем молча** — помечаем как устаревшее и ставим ссылку на новое.
4. **Скил должен быть коротким.** Всё, что нужно не всегда, уходит в `references/`.
5. **Каждое «нельзя» — с причиной.** Правило без причины нарушат при первом же неудобстве.

## Что НЕ читать

- `skills/` в корне репозитория (без точки) — **архив** старой системы, описывает игру до сброса 01.06.2026.
- `CLAUDE.md` — **устарел**, описывает до-сбросную архитектуру.
- `src/styles/hexlash-ui.css` и `src/styles/v24/` — легаси-слои стилей.
